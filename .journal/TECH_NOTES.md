# Technical Notes

- The template's current example operator is `NginxDeployment` in `example.meigma.io/v1alpha1`; it owns a same-named ConfigMap, Deployment, and ClusterIP Service.
- Because owned children are same-named, `NginxDeployment` names are validated as Service-safe DNS labels no longer than 63 characters. Inline `spec.config` is capped at 64 KiB before it is copied into a ConfigMap.
- The demo workload uses `nginxinc/nginx-unprivileged:stable` on port 8080 with Restricted-compatible pod/container security settings and resource requests.
- Manager startup uses Kong for CLI parsing and `slog` via `logr.FromSlogHandler` for controller-runtime logging. Deployed manager flags remain stable, but zap runtime flags are intentionally not preserved; use `--log-format=json|text` and `--log-level=debug|info|warn|error`.
- `cmd/main.go` is intentionally a short startup outline. Runtime construction lives in `cmd/manager.go`, while scheme registration, controller registration, health checks, and Kubebuilder scaffold markers live together in `cmd/setup.go`.
- Deployment manifests live in `charts/template-k8s`; the old Kustomize `config/` tree was removed. `root:generate` writes generated deepcopy code and CRDs, `root:deploy` applies those CRDs before `helm upgrade --install`, and chart RBAC drift is tested against temporary controller-gen output.
- Moon is the task front door for this template, but the task surface should stay small to avoid recipe fatigue. Use `moon run root:generate`, `moon run root:check`, `moon run root:test`, and `moon run root:test-e2e` for controller/API changes. `root:check` covers formatting, golangci-lint, generated drift, Helm chart validation, and Chainsaw manifest linting; `root:test` stays separate because it wraps `setup-envtest`.
- The local operator dev stack is Proto-managed with `kind`, `ctlptl`, `tilt`, and `ko`. Use `moon run root:dev-up` and `moon run root:dev-down` for the interactive loop. `ctlptl` owns the Kind cluster `template-k8s-dev` and local registry `template-k8s-registry` on `127.0.0.1:5005`; Tilt requires Kubernetes context `kind-template-k8s-dev`, renders `charts/template-k8s`, and builds/injects the manager image through `ko` for `./cmd`.
- Repo-local tools are expected to be on `PATH` through `.envrc` locally and `moonrepo/setup-toolchain` in CI. Moon tasks should call tools directly, such as `golangci-lint`, rather than wrapping them with `proto run`.
- Linting intentionally avoids custom `golangci-lint` binary builds. The Kubebuilder `logcheck` module plugin was removed in favor of the normal pinned binary and built-in `loggercheck`.
- Release Dry Run keeps a broad `pull_request` trigger so required check contexts still report on ordinary PRs, but the binary/container dry-run jobs intentionally skip unless the run is manual or the PR head branch starts with `release-please--`.
- Release Please updates `charts/template-k8s/Chart.yaml`; the tag release workflow publishes binaries, the multi-platform container image, and the Helm chart as `oci://ghcr.io/meigma/template-k8s/chart`. The chart metadata name is intentionally `chart` for the OCI basename, while helpers preserve rendered `template-k8s` identity. Helm chart attestation requires Docker-style GHCR login in addition to `helm registry login`, and reruns recover the already-published chart digest with `helm show chart`.
- The Helm chart has an optional `kyverno.imageVerification` block that renders a Kyverno `ClusterPolicy` for release-produced operator image attestations. It is disabled by default and the default keyless identity trusts `.github/workflows/release.yml` only at SemVer tag refs, not `refs/heads/master`; `v0.1.2` was verified with tag provenance in a Kind/Kyverno smoke.
- Repo-local Kubernetes operator lessons live in `.agents/skills/k8s-operator/SKILL.md`.
- Test layering is intentional: envtest owns the controller/API behavior matrix, including manager-backed watch/predicate/index coverage; Chainsaw owns Kind-backed chart install/runtime smoke and should not duplicate envtest edge cases.
- Operator-specific observability is intentionally finite-label and injectable: `internal/controller/telemetry` registers NginxDeployment child apply and status transition counters with controller-runtime's metrics registry, and wraps Kubernetes Event emission for aggregated child apply events plus persisted availability condition reason changes.
- Controller reconcile logging should stay signal-oriented: log actual side effects and persisted user-visible condition transitions at info level, and keep lifecycle/no-op details behind `V(1)`.
- Kubebuilder API type godoc is projected into the CRD `description` by controller-gen. Any change to a type's doc comment (including punctuation) requires `moon run root:generate` before pushing, otherwise `root:check` fails on the resulting drift in `charts/template-k8s/crds/`.
- `README.md` is intentionally a downstream-facing placeholder template, not documentation about the `template-k8s` repository itself.
- `DELETE_ME.md` is the canonical first-setup checklist for repositories generated from this template. It should be deleted by downstream projects after they replace project identity, API/reconciler code, Helm paths, release automation, tests, and agent guidance.
- `.github/scripts/configure_github_repo.py` and `.github/repository-settings.toml` were copied from `template-go` in session 009. The settings file is not yet customized for operator-specific required checks beyond the copied defaults.
- Tooling migrated from Proto to **mise** (session 015): `mise.toml` + committed `mise.lock` (fail-closed `locked=true`) replace `.prototools`/`.moon/proto/*`/`.envrc`/`.go-version`; moon runs `system` binaries (`toolchains.default: system`); CI uses `jdx/mise-action`. 10 tools use verifying `aqua:` backends (chainsaw via full path `aqua:kyverno/chainsaw`); `controller-gen` uses `go:sigs.k8s.io/controller-tools/cmd/controller-gen` (no aqua package). Local validation needs the host's stray go (`~/.proto/bin/go`, `~/.goenv/shims/go`, `GOPATH=~/go/1.26.4`) neutralized — run gates via `mise exec -- bash -c 'strip /.proto/shims from PATH; unset GOROOT; moon run …'`.
- The release operator image is built by **melange + apko** (session 015), not a Dockerfile (deleted): `melange.yaml` compiles `./cmd` → `/usr/bin/manager` signed Wolfi apk, `apko.yaml` assembles the minimal multi-arch nonroot (uid 65532) image. `ko` remains the local Tilt dev builder; `dev/image-build.sh` builds the apko image for the Kind e2e. Image is keyless-cosign-signed + syft-SBOM-attested.
- Release **provenance is SLSA L3** (session 015): generated in the reusable `.github/workflows/attest.yml` (isolated OIDC), not inline. `release.yml` has `attest-binaries`/`attest-image`/`attest-chart` callers; every caller must grant `packages: write` (reusable workflow can't exceed caller perms). The chart's Kyverno `attestor.subjectRegExp` trusts **`attest.yml`** at SemVer tag refs; `attest-build-provenance` preserves the `slsa.dev/provenance/v1` + `buildtypes/workflow/v1` predicate the policy checks. cosign signing stays in `release.yml` (separate signer).
- `root:check` runs only the RBAC-drift chart test (`go test ./test/chart -run TestManagerRBACMatchesControllerGen`); the full chart-render suite (incl. the Kyverno `subjectRegExp` assertion in `test/chart/rbac_test.go`) only runs under `root:test` (`go test ./...`). **Validate chart `values.yaml`/template changes with `root:test`, not just `root:check`.**
